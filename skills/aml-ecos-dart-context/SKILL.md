# AML–ECOS–DART 협업 분석

## 목적

익명화된 CAMS/TPAC 사례 또는 FATF·ACAMS·유사 AML 문서를 읽기 전용으로 검토한다. 결과는 한국은행의 거시·금융안정 관점, FIU·금융감독원의 AML·감독 및 DART 공개공시 관점을 하나의 **공개정보 기반 협업 검토 설계**로 정리한 분석보고서와 5–10분 설명대본이다.

개별 의심거래 확정, STR 제출, 제재·거래 제한, 실제 기관 간 정보공유·공동조사 결정을 수행하지 않는다.

## 필수 통제

- 원본 파일·메타데이터·사례 데이터를 수정, 정규화, 덮어쓰기 또는 외부 전송하지 않는다. 분석용 요약은 원본과 분리한다.
- 문서 주장, ECOS·DART 등 공개 확인 사실, 분석가 가설, 정책·운영 제안을 반드시 구분한다.
- 실명, 계좌·지갑 주소, 인증정보, 주민번호 등 불필요한 민감정보를 요구하거나 출력하지 않는다.
- DART는 `corp_code`, 종목코드 또는 사용자가 확인한 법인명처럼 검증 가능한 식별자가 있을 때만 조회한다.
- ECOS와 DART 조회는 읽기 전용이다. 필요한 API·접근 권한이 없으면 수치를 추정하지 않고 `조회 불가`로 기록한다.

## 시작 전 라우팅

- 문서(PDF, 웹페이지, 전사본, 메모)를 입력받으면 [문서 입력과 반복 루프](references/document-loop.md)를 읽는다.
- CAMS/TPAC 거래 사례를 입력받으면 [사례 입력 스키마](references/case-schema.md)를 읽는다.
- 보고서 또는 설명대본을 만들면 [보고서·대본 형식](references/report-and-script.md)을 읽는다.

## 공통 작업 순서

1. **사실 고정**: 출처·발행일·문서 형식·페이지 수·접근일, 또는 거래기간·통화·국가·유형을 기록한다.
2. **위험 논지 분해**: 위험 유형, 채널·자산·통화·국가, 통제 공백, 국제 전이 경로를 추출한다.
3. **증거 게이트**: 법인 식별자가 있는지 확인한다. 없으면 특정 DART 기업을 검색·추정하지 않고 `DART 연계 미확인`으로 남긴다.
4. **ECOS 맥락**: 기간·통화·거래성격과 직접 맞는 지표만 선택하고 지표명·값·단위·기준시점·제한을 기록한다.
5. **DART 맥락**: 식별자가 있을 때만 해외사업·외화 노출·차입·자금조달·주요사항·감사의견·재무제표 중 직접 관련 공시를 확인한다.
6. **협업 카드**: `문서/사례 근거 → 한은·ECOS 거시 트리거 → FIU·금감원/DART 점검 게이트 → CAMS 질문 → 반증 후보 → 한계`를 한 행으로 작성한다.
7. **납품과 검수**: 보고서와 대본이 같은 근거·한계를 쓰는지 확인한다.

## 상태 라벨

- `확인됨`: 입력 원본 또는 공식 공개 원문에서 직접 확인.
- `정합성 검토 필요`: 시간·주제상 함께 볼 수 있으나 인과·동일 거래를 증명하지 않음.
- `연계 미확인`: 식별자, 기간, 공시 또는 지표 근거가 부족함.
- `반증 후보`: 정상 사업, 계약, 환율, 계절성 등으로 설명될 수 있어 추가 확인이 필요함.

## 완료 조건

좋은 결과는 위험점수가 아니라, 최소 한 개의 협업 카드에 원문 또는 사례 근거, ECOS 맥락 또는 조회 불가 사유, DART 처리 또는 연계 미확인, CAMS 확인 질문, 명시적 한계를 모두 제공하는 것이다.
